OFA LiveWhale widget frames

One page per LiveWhale calendar widget, each rendering a single widget with a transparent background so it can be iframed into ofa.fas.harvard.edu, which strips the widget's own script tag. Marked noindex and linked from nowhere — these pages exist only to be framed.

What these pages change

Beyond hosting the widget, each frame corrects three things in LiveWhale's own markup and CSS:

  • Always 4 columns. LiveWhale ships repeat(auto-fill, minmax(300px, 1fr)) plus per-widget rules that give 3 columns above 910 px and 4 above 1310 px, so any page with a sidebar silently drops to 2–3 columns. Since a frame's viewport is the host page's embed column, a media query inside the frame reads the host layout directly and pins 4 columns on full-width and sidebar pages alike.
  • No horizontal overflow. A bare 1fr track floors at the item's min-content width, which the event photo pins at its intrinsic 445 px — so on narrow containers the grid overflowed and got clipped. minmax(0, 1fr) fixes it.
  • Photos actually scale. LiveWhale's image rules target div.widget-photo-space > span > a > img, but it renders the photo two levels deeper than that, so the rule never matched and images sat at full size. These frames match what LiveWhale really emits and give every card a uniform 4:3 photo.

widget-frame.js also forces the event photos to load eagerly — LiveWhale injects them after the document's load event, so Chrome never runs its lazy-load check and every image slot stayed blank — and posts the rendered height to the parent window for optional auto-resize.

Picking a height

With 4 columns pinned, a card's height is driven by its photo, so the tallest render is now the widest container. That means one fixed height covers a page's whole responsive range — just size it for the widest the embed column ever gets.

Notes

  • Below 640 px the grid steps to 2 columns, and below 420 px to 1, so phones stay legible. Those layouts are taller than the fixed height, so the frame scrolls internally on small screens.
  • Drupal replaced the title attribute with "Widget" on /ofa-calendar. If the embed component has its own title field, set it to something descriptive — screen readers announce it.
  • Links open in a new tab (base target="_blank"), since the sandbox has no top-navigation permission. Adding allow-popups-to-escape-sandbox is worth considering, so the opened events.college.harvard.edu page is a normal tab rather than inheriting the sandbox.
