OFA calendar widget — as LiveWhale ships it, and as restyled

Both panels below embed the same LiveWhale widget (id 44, the OFA Calendar feed from events.college.harvard.edu), pulling the same live events. The only difference is the CSS applied around it.

What is held constant, so this is a fair comparison and not a flattering one. Both frames get a transparent background, a zeroed body margin, and two non-cosmetic fixes: eager-loading the event photos, and reporting their height to this page so neither panel scrolls inside a fixed box.

The photo fix matters. LiveWhale marks its event images loading="lazy" but injects them after the document has already fired load, and Chrome never runs its lazy-load check on images added to a complete document it is not scrolling — so the photo slots stay blank forever. Without that fix in both panels, the stock half would look broken for a reason that has nothing to do with styling.

So everything you see differ below is CSS.

What the restyle actually does — it is all override CSS, no change to the feed or its configuration:

• Forces a 4-column grid. LiveWhale ships repeat(auto-fill, minmax(300px, 1fr)), which collapses to 3 or 2 columns inside any page with a sidebar.
• Repairs the event photos. LiveWhale's own image CSS targets div.widget-photo-space > span > a > img, but it renders the photo two levels deeper than that, so its rule never matches and the image never scales — it is placed into a 4:3 box with object-fit: cover instead.
• Matches the site's body typeface and text colour.
• Steps the grid down at 1000px, 640px and 420px so it stays legible on a phone.

Open question, flagged rather than guessed: the production frame requests Source Sans Pro as the site's body font, while the palette recorded in the tooling repo names museo-sans. One of the two is stale. Worth settling by reading the live page's own inline --hwp-* properties.
